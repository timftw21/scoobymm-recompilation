# Source correctness audit

Reviewed all 48 tracked files under `src/` at commit `24ca76f` on 2026-11-21. The supported XISO, the executable inside it, and focused Windows x64 probes are the primary evidence. The repair results below apply to the rebuilt working tree. The subsequent audit sections describe the original revision and preserve its reproduction measurements.

### Environmental effects reference

The verified XBE passes effect indices 0 and 1 at `0x00019314–0x00019324`. The rebuilt guest loader decrypted four programs from `STREAM/DSP/bidon.bin` and seven from `STREAM/DSP/simple.bin`. The first effect in `bidon.bin` is a gain-and-mix loop. Two subsequent effects issue scratch-memory transfers. The XBE initialization at `0x000D15A9` identifies the separate 0x5CC-byte sound processor control program at Xbox address `0x000EA6F0`. That program loads the effects and runs them for each 32-frame audio block. [Microsoft's DSP image and routing description](https://patents.google.com/patent/US7076774B2/en) · [xemu's Xbox sound-processor interface](https://github.com/xemu-project/xemu/blob/711b416840c2a528cb989621b6456a72bd02d768/hw/xbox/mcpx/apu/dsp/gp_ep.c)

Two independent CPU implementations ran the original control program with each disc image. The fixture sent a half-scale impulse into each of the 32 input channels separately, followed by a separate mixed-input case. It recorded all six speaker channels for 160 blocks per case. The two implementations produced identical output bytes across all 33 cases for each image. On the four-effect image, input 6 produced a long left-speaker response, input 10 produced silence on the left and input 11 again produced a response. A generic room filter would give the game different output.

## The reported audio failure

**The native game code can submit stereo music to a mono dialogue stream.** I reproduced the reported header with the original recompiled streaming routine, the native audio service and the two files from the verified disc. The mixer at `src/xbox/audio.cpp:296` silences a block after receiving the wrong packet. Other pieces of the same music can look like valid mono blocks and still play, and the guest can receive a successful packet completion.

| Disc evidence | Observation |
| --- | --- |
| `STREAM/EN/GLOBAL/HEROES/SCO506EN.XB` | Mono, 44,100 Hz, 36 bytes per 64 frames. The data starts at file offset 48 and contains 22,284 bytes. All 619 block headers passed the index and reserved-byte checks. |
| `STREAM/MUC1.XB` | Stereo, 44,100 Hz, 72 bytes per 64 frames. Offset 921,648 starts a stereo block with header `E3 18 26 00 38 22 28 00`. All 16 stereo blocks in the implicated 1,152-byte packet passed the same checks. |
| Music file offset 921,684 | The bytes `08 CA FB 99` are 36 bytes into the stereo block. They are compressed samples. Reading them as a mono header interprets `FB` as a step index of 251, outside the valid range 0–88. |
| Earlier playtest | At scanout 2,644 the log reports voice 1, mono, packet size 1,152, block 1, offset 36 and `08 CA FB 99`. Its copied source is reported as address zero. Its recent I/O includes the short dialogue read. The log lacks the prior contents of the two stream buffers and the packet-completion timing. |

The independent Xbox IMA implementation also accounts for 64 output frames per block and channel-dependent block sizes. [vgmstream Xbox IMA decoder](https://github.com/vgmstream/vgmstream/blob/master/src/coding/ima_decoder.c)

The earlier local probe in `build/adpcm-crash-probe.cpp` overwrote four bytes of a dialogue packet with the reported header and checked that playback continued. That exercised the decoder's recovery behavior. It bypassed the title code that chose which bytes to submit.

### Where the handoff goes wrong

1. The stream uses two 36,864-byte buffers and three output packet slots. At Xbox address `0x00028EA5` the title initializes the first buffer's remaining byte count at object offset `+0xAC` to 36,864. The worker clears the first buffer at `0x0002925C`. The read completion at `0x0001AB22` publishes the actual length to the buffer descriptor. For this dialogue file the actual length is 22,284.
2. At `0x00029324–0x000293BE` the worker recognizes the short read, marks the buffer ready and reaches its final state. The stream still consumes the full 36,864-byte capacity. The extra 14,580 bytes amount to 405 silent mono blocks, about 0.588 seconds at 44,100 Hz.
3. The routine at `0x000293F0` checks the current buffer's ready flag at `0x00029456–0x0002946C`, then visits the available packet slots. It copies at `0x00028F39`, submits at `0x00028F50`, and switches buffers at `0x00028FCC–0x00028FF7`. If a second slot is free in the same pass, the loop at `0x00029473–0x0002948E` reaches the copy again without checking readiness on the newly selected buffer.

For the replay, the first buffer contained the real dialogue and its cleared tail. The second buffer was marked **unready** and seeded with prior music data starting at `48 + 25 × 36,864` in `MUC1.XB`. The real recompiled routine selected the copy source and submitted the packets. A single guest thread modeled uncontended locking. Only the availability of the next output slot changed between the two runs.

| Free slots at the buffer switch | Packets submitted | Result |
| --- | ---: | --- |
| One | 32 | The first buffer drained, including its silent tail. No invalid header. |
| Two | 33 | Packet 33 came from the unready second buffer. All 1,152 bytes matched the stereo music on disc. The first invalid mono header was `08 CA FB 99` at packet offset 36. |

This establishes a causal path through the verified title code. The previous playtest's exact buffer history and whether original Xbox hardware exposes the same timing remain open. **The repair belongs at the stream handoff.** Honor the completed read length on the initial fill, check the newly selected buffer before each submission, and drain already submitted packets at EOF. Check short first and final reads, looping, flush, and the two-slot boundary against the original timing before adopting a title-specific change. A replay passes when every submitted byte belongs to the active stream and the final completion has the right duration. A zero count of invalid headers alone already passes the faulty one-slot control.

To distinguish a title bug exposed by legitimate Xbox timing from one exposed by native scheduling, the missing observation is a trace of this transition on the original system. It needs the file and byte range of the last fill for each buffer, its completed length and ready flag, and which packet slots were free when the title switched buffers. Another recording of the decoder warning alone cannot answer that question.

## Remaining acceptance gaps

The compiled gameplay target is gated to 64-bit Windows and uses MASM, Win32 fibers and a Win32 window handle. Linux DXVK Native and Intel/Apple Silicon macOS gameplay remain unverified. The player has fixed keyboard bindings and lacks the requested persistent settings and remapping interface. The guest language setting is fixed to English at `src/xbox/boot.cpp:1221`. French and German mode, widescreen camera/HUD framing, and end-to-end save/reload need separate verification.

An existing 640×480, VSync-off Windows recording on a Ryzen 5 5600X and RTX 5060 Ti measured 30.08 scanouts/s, 33.24 ms median and 39.22 ms at the 99th percentile. It counted 65 guest flips, 65 presentations and 65 engine updates, with 64 frame-time samples. That run missed the 2.778 ms target and covered one short interval. Source also shows synchronous shader compilation on a cache miss and routine checkpoint history collection during normal play. Comparable cold/warm widescreen menu, exploration, capture and minigame measurements remain outstanding.

No original-console session, full playthrough, or matched audiovisual comparison was performed for this audit. In particular, character switching, puzzle progression, ghost captures, minigames, cutscene transitions and audio/video sync still lack an end-to-end verdict here. The disc establishes the bytes the game starts with. It cannot by itself establish Xbox scheduling, appearance or sound.

## Reproducing the focused results

The first command after the disc lookup runs the permanent `check-dialogue` diagnostic included in the native tool. It reads both original assets from the supplied disc, drives the compiled stream pump through both packet schedules, and checks the exact packet bytes and completion frame. The extra probe executables and their sources live under `build/correctness-audit/` in this Windows workspace.

```powershell
$iso = (Get-ChildItem 'Scooby-Doo! Mystery Mayhem' -Filter '*.xiso.iso').FullName
& .\build\xbe-compiled\native-recompiler.exe check-dialogue .\data\local\default.xbe $iso
& .\build\correctness-audit\replay.exe .\data\local\default.xbe $iso
& .\build\correctness-audit\services.exe .\data\local\default.xbe
& .\build\correctness-audit\texture.exe
& .\build\correctness-audit\cubemap.exe
& .\build\correctness-audit\packet-split.exe
& .\build\xbe-compiled\native-recompiler.exe boot .\data\local\default.xbe 1000 0x11C5C --disc $iso --frame .\build\correctness-audit\nonexistent-frame.png
```

Historical local evidence used here is in `build/logs/playtest-17952901592725850.json` and `build/captures/verify-20261121-125541-545/performance/performance.json`. The texture probe used software D3D11 and private access to select the texture for drawing. The file probe used isolated in-memory storage. Neither probe establishes how frequently the corresponding error occurs during ordinary gameplay.
